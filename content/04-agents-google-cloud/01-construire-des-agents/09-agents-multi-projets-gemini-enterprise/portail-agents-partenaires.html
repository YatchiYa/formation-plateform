Make your agent available in Gemini EnterpriseRendez votre agent disponible dans Gemini Enterprise

Your agent stays in your Google Cloud project. You grant one permission to our Gemini Enterprise service account, check that the permission is in place, and send us a request. We review it and publish the agent to the groups you choose.

Votre agent reste dans votre projet Google Cloud. Vous donnez un seul droit au compte de service de notre Gemini Enterprise, vous vérifiez que ce droit est en place, et vous nous envoyez une demande. Nous la relisons et publions l'agent pour les groupes que vous indiquez.

How it worksComment ça marche

You never need access to our project, and we never need access to yours. The only link between the two is one IAM permission that you grant and can revoke at any time.

Vous n'avez jamais besoin d'accès à notre projet, et nous n'avons jamais besoin d'accès au vôtre. Le seul lien entre les deux est un droit IAM que vous donnez, et que vous pouvez retirer à tout moment.

Service accounts and connectionComptes de service et connexion

Three identities are involved. None of them needs a key: Google signs every call. Never create or send a service account key.

Trois identités interviennent. Aucune n'a besoin de clé : Google signe chaque appel. Ne créez et n'envoyez jamais de clé de compte de service.

Agent Runtime

Gemini Enterprise calls the Agent Runtime API in your project with its service account. Google's documented permission is the role Discovery Engine Service Agent on your project.

Gemini Enterprise appelle l'API Agent Runtime de votre projet avec son compte de service. Le droit documenté par Google est le rôle Discovery Engine Service Agent sur votre projet.

This role applies to the whole project. Host the agents you expose in a project dedicated to them, not next to unrelated workloads.
Ce rôle vaut pour tout le projet. Hébergez les agents que vous exposez dans un projet qui leur est dédié, pas à côté d'autres charges.

A2A · Cloud Run

Gemini Enterprise sends a Google-signed OIDC token for its service account in the X-Serverless-Authorization header. Cloud Run checks it: you grant Cloud Run Invoker on that service only. The service stays private. The Authorization header stays free: it carries the user's OAuth token only if an authorization is configured (see FAQ).

Gemini Enterprise envoie un jeton OIDC signé par Google pour son compte de service, dans l'en-tête X-Serverless-Authorization. Cloud Run le vérifie : vous donnez Cloud Run Invoker sur ce service seulement. Le service reste privé. L'en-tête Authorization reste libre : il porte le jeton OAuth de l'utilisateur seulement si une autorisation est configurée (voir FAQ).

Works only with the default …run.app URL. API keys, static headers and the security fields of the agent card are not used.
Fonctionne seulement avec l'URL …run.app par défaut. Les clés d'API, les en-têtes fixes et les champs de sécurité de la carte ne sont pas utilisés.

Security and complianceSécurité et conformité

Gemini Enterprise's own Model Armor does not filter external agents. Your agent must screen its own inputs and outputs (Model Armor plugin or equivalent). We check this before publishing.
Le Model Armor de Gemini Enterprise ne filtre pas les agents externes. Votre agent doit filtrer lui-même ses questions et ses réponses (plugin Model Armor ou équivalent). Nous le vérifions avant la publication.
