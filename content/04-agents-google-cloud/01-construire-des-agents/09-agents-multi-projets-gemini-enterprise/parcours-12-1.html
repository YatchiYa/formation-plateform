Des agents dans un projet, utilisés dans l'app Gemini Enterprise

Vos agents vivent dans un projet des agents (un projet Google Cloud « X »). L'app Gemini Enterprise vit dans un autre projet, le projet de l'app. Ce parcours fait le chemin complet : déployer les agents, prouver que l'app pourra les appeler, les brancher sur l'app, et les agents qui agissent avec le compte de l'utilisateur. Chaque commande et chaque résultat de cette page a été testé pour de vrai.

2. Comprendre

  

    

      
Deux projets, un seul sens d'appel

      

      
L'app appelle les agents avec son compte de service. Le projet des agents
        l'autorise (deux droits), puis l'app ajoute les agents. Ces droits ne donnent rien aux
        utilisateurs : qui peut utiliser un agent, c'est le rôle Agent User, donné dans l'app.

    

    

      
Les deux droits (tous dans le projet des agents)

      

        
#RôleSur quoiPour

        
          
①Demandeur Cloud Run
roles/run.invoker		Un service Cloud RunChaque agent A2A

          
②Agent de service Discovery Engine
roles/discoveryengine.serviceAgent		Le projet entierLes agents Agent Runtime (une fois)

        
      

      
Qui les donne ? Celui qui possède le projet des agents : l'équipe de l'agent. Délai : 2 à
        3 minutes. Le circuit avec une équipe cliente (messages à envoyer) : 12-1-4, partie 3.5.
